# 我的 AI 工具箱：按任务而不是按产品选择工具

AI 工具更新得很快。真正容易让人疲惫的，不是工具不够，而是每次遇到新任务都要重新判断“该打开哪个”。更可靠的做法是先为任务分类，再为每一类准备一个默认工具和一个备用工具。

## 先写任务，不要先搜工具

我把日常需求分成四类：理解信息、生成初稿、处理重复步骤、辅助编程。一个工具即使很强，也不必承担全部工作。

| 任务 | 先问自己的问题 | 期待的输出 |
| --- | --- | --- |
| 理解信息 | 我需要事实、解释还是对比？ | 要点、疑问、下一步 |
| 生成初稿 | 我已有素材还是只有一个想法？ | 可修改的结构或初稿 |
| 重复步骤 | 这件事每周会重复几次？ | 可复用流程 |
| 辅助编程 | 我能给出哪些代码与约束？ | 小范围、可验证的改动 |

这张表的作用，是阻止自己在“工具试用”上花掉真正的工作时间。

## 给每类任务设一个默认入口

默认入口不是唯一选择，而是减少犹豫的起点。例如，阅读资料时先用一个擅长总结和追问的对话工具；写作时先从大纲开始；自动化只处理有明确输入和输出的环节；编程始终从当前仓库和具体报错开始。

当默认入口连续两次不合适，再记录原因并调整。不要因为一次惊艳的演示就替换整套流程。

## 用“输入—处理—验收”评估工具

每次试用一个工具，我只记录三件事：

1. **输入成本**：需要复制多少资料、补多少背景？
2. **处理质量**：它是否能遵守边界，还是只会给漂亮的泛话？
3. **验收成本**：我需要花多久核对、修改或重做？

如果一个工具节省了生成时间，却让验收时间翻倍，它并没有提高效率。

## 一个简单的工具箱模板

可以在笔记里维护下面这张清单：

```text
任务：把一篇文章变成学习笔记
默认工具：对话式阅读助手
输入：文章链接或正文 + “提取论点、证据、我的疑问”
验收：逐条回看原文；保留出处
备用方案：手动列出三条结论，再请工具补反例
```

工具名称会变，任务模板不会。长期有价值的是你对输入与验收的控制力。

## 小结

先用任务给工具定位，再用验收成本淘汰不合适的工具。这样你的工具箱会越来越小，却越来越顺手。
