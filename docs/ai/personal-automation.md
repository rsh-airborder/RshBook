# 从重复操作开始：设计一个个人自动化工作流

自动化最适合解决“规则稳定、频率较高、人工价值很低”的步骤，而不是把每件事都交给系统。一个好的个人工作流，应该让你少做搬运，多做判断。

## 先找一个真正重复的动作

连续一周记录自己反复做的操作：复制链接、整理文件名、发固定格式的提醒、把零散素材归档。只有当一个动作每周至少出现两三次，才值得考虑自动化。

不要从最复杂的任务开始。复杂任务通常包含大量隐性判断，过早自动化只会把混乱固化下来。

## 画出最小流程

用四个问题描述流程：

1. 触发条件是什么？
2. 输入来自哪里？
3. 系统要做什么转换？
4. 输出交给谁，如何验收？

例如“收集待读文章”：浏览器收藏触发 → 读取标题和链接 → 生成一条 Markdown → 写入收集箱。每一步都应能独立检查。

## 为异常保留人工出口

自动化的关键不是永远不出错，而是出错时不制造更大问题。对于不完整输入、重复内容、涉及外部发布的动作，先把结果放到待确认列表，不要直接发送或覆盖原数据。

一个实用规则是：自动化可以创建草稿、整理数据、发出提醒；涉及删除、付款、公开发布时必须人工确认。

## 从半自动开始

首版只做一半：系统准备材料，你点击确认。观察一两周后，再决定哪些确认可以取消。半自动往往已节省大部分时间，同时保留对结果的掌控。

## 上线前清单

- 输入为空时会发生什么？
- 重复触发会不会产生重复输出？
- 输出是否可回滚或可追踪？
- 是否有一处能看到失败记录？
- 停用后，原有流程是否仍可手动完成？

从一个小而稳定的动作开始，你的自动化系统才会真正越用越可靠。
